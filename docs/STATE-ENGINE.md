# Task4 state engine boundary

`createInitialState(culture, optionalStartupPreferences)` creates a fresh Flan1 selection, independent sparse banks, unique route history, family settings and a null retained view. Its first rendering requires a real registered route. Optional preferences are a new account-adapter seam: only explicit new-workspace creation consumes them. Configure/reset/replay/resume never query an account or update account defaults. The existing branch and source data remain unchanged.

`registerRoutes(routes)` builds an immutable registry with separate classifications for implemented source dispatch, required-but-pending dispatch, evidenced no-dispatch ids and unknown requests. `transition(state,action,catalog,registry?)` and `replay` accept an explicit registry; the stable three-argument boundary uses an empty registry until the real family modules are assembled. Calling a pending route throws a development error. Unknown external ids never recover silently to Flan1. Tests use clearly labeled test-only renderer adapters to isolate transition mechanics; they do not count as route implementations or numeric parity.

Clicker order is unique-history update → LoadSettings → GetTitle → AddChecks → shared option preparation → route dispatch. Each accepted action advances revision once; caller input remains unchanged. Private state contains family-scoped saved fields and the retained complete view needed for source no-dispatch behavior. Existing route visits preserve the history cursor; new ids append, retaining future entries rather than browser-style truncation. An eleventh unique id shifts the ten-entry stored window. Disabled back/forward endpoints clamp at bounds. These source quirks are intentional.

LoadSettings preserves the original corrections before missing-MainSize defaults: threaded-fitting ratings, Ftbw11/Flan6 schedules, restricted Flan classes, high-DIN sizes/classes, butterfly classes and strainer classes. Family subtabs share their stored fields; unrelated families do not. Defaults preserve sequential repeated branches, including both Fswa blocks. Configuration uses the wired `frmConfigs.Button4_Click` order and Single arithmetic. The two Fxly visits share one family store, so temperature changes occur twice; unit changes reset their shared length to100000/4000. Fswa1/Fswa2 saves occur without intermediate loads and carry current selection values, as source does. Piwt conversion lookups preserve source iteration order and exact lexical equality; final route recipe acceptance remains later work.

AddChecks resets selector eligibility counts and menu/subtab check flags, resets six button widths/dropdown arrows, and clears Label1–6 while retaining Label7 and the drawing. Thus stale Blnd is a source no-dispatch state with retained geometry, cleared headers and no invented dimensions. Original title/standard strings are imported as inert title constants, not reconstructed source or executable code. Shared option labels preserve the evidenced order and unit-specific API labels; source enabled-array counts need not equal the populated item count (e.g. DIN/ValveClass). Route modules own their final eligibility and presentation.

Search uses the source file order and original ids/descriptions. It uppercases using Framework-compatible simple casing without trimming, checks columns2–5, and runs all four Binary Like checks without short-circuiting. The standard in column6 is not searched. `SearchHit={id,text}` is independently public. `searchCatalog` is a pure internal query helper; errors are never converted to empty results. The user search operation must call the revisioned `search` action: ordinary search changes query scratch/revision only, whereas a reached malformed pattern invokes source ErrorCatch and returns the actual reset state. A later HTTP search API must preserve this write boundary instead of hiding it in an independent read request.

Sensor unavailable checks distinguish null/empty/N/A from SPA/numeric text. A source-specific unavailable view clears headers and paints only white, retaining the selector choices; it is distinct from ErrorCatch. ErrorCatch applies defaults in the original order, selects Flan1 and dispatches it, with Alfadata identity copy. It cannot succeed if the required Flan1 implementation is pending. Route calculation modules own their source-local exception catches; unexpected missing implementations are never a manufactured success. The existing `reset` action is a workspace-local command applying current-route selection defaults, with current units/history and account preferences retained; it does not expose the vendor distribution/registry reset tool.

Private traces retain explicit source table/one-based row/column/raw lexical selection through `readCatalogCell`; buffers remain sparse and source-indexed. Traces, settings, buffers, evidence and source paths remain absent from the separate public result contracts. Text-results inventory identifies headers, controls, labels/units and dimension messages, with representative Flan1 labels/columns/units pinned in evidence/state-compatibility.json. Independently declared private/public minimal text-results types carry explicit availability and exact string rows; unavailable views have no fabricated result rows. Private persistence recursively validates their shape. Each route recipe must establish its actual semantic values before the later strict public projection/results panel. No semantic values are inferred from drawing coordinates or guessed engineering labels here.

State persistence uses codec1/schema2; see STATE-FORMAT.md for exact grammar, strict nested validation, old-schema migration and continuation limits. No PostgreSQL, full-route drawing renderer or UI acceptance is claimed by this task.
