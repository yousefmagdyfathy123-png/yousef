# Trial recovery

The trial is an Alfadata account feature. A verified user explicitly enters the workspace through a protected POST. Signup, email verification, sign-in, account reads, and workspace prefetch perform no trial write. The decision interval is 120 elapsed hours in UTC. At the end instant, trial access expires. Verified paid access takes precedence over expiry or trial review. Suspension takes precedence over both.

## Registry and identity

The registry owns the immutable decision. PostgreSQL stores a mirror and the epoch under which it was reconciled. The server rechecks the active session, verified identity and suspension after registry I/O. A lost response triggers another lookup for the same subject. If the registry committed before PostgreSQL failed, the next entry mirrors the original decision.

Set `TRIAL_REGISTRY_NAMESPACE`, `TRIAL_IDENTITY_KEY_REF`, `TRIAL_IDENTITY_KEY_HEX` (32 random bytes in hex), and `TRIAL_MIRROR_EPOCH`. Keep the key and its stable reference recoverable outside the PostgreSQL timeline. Identity v1 uses the pinned Better Auth lowercase email rule. It makes no alias or dot transformations. The namespace is bound to the key reference and key material. A wrong key or reference cannot query the original namespace as authoritative. Rotate registry credentials and secret-manager wrapping independently of the fingerprint key. Replacing the fingerprint key requires an authoritative, tested cross-version mapping that preserves decisions even for identities absent from PostgreSQL. Keep serving the existing key until that mapping is available. Starting a fresh namespace as a rotation would lose prior trial evidence.

Development can set `TRIAL_LOCAL_REGISTRY_FILE` to an absolute path on a local disk outside the PostgreSQL data directory. With the settings above exported, initialize a new development store using `node --import tsx tools/trials/init-local.ts`. Provision a fresh file only for a new test/development environment. Missing metadata and mismatched namespaces return unknown. The local adapter uses a SQLite transaction with a unique subject key and full synchronous commits. Test storage can survive a PostgreSQL restore on the same host. Production resilience requires independently durable storage.

Production configures `TRIAL_REGISTRY_URL` (HTTPS) and `TRIAL_REGISTRY_TOKEN` through deployment secrets. The adapter POSTs a bearer-authenticated JSON object with `operation` (lookup or createIfAbsent), `namespace`, `subjectId`, and `proposed` for writes. A successful response echoes the namespace and returns `status` of found, absent or unknown, plus a strict decision for found. The configured service must validate its current namespace, provide authoritative reads, and atomically persist one decision per subject before returning it. Transport errors and unexpected replies are unknown. Confirm TLS, secret recovery, off-host failure isolation, durable writes and registry backups with the actual service before launch.

## Restore and recheck

1. Keep trial access fenced while restoring PostgreSQL. Preserve the registry and fingerprint keys outside the restore timeline. Verify the registry is current, independently backed up and authorized for the configured namespace.
2. Deploy a new shared `TRIAL_MIRROR_EPOCH` before serving requests from the restored database. An earlier epoch requires evidence from the current registry. If registry currency is uncertain, keep trial configuration disabled. Independently reconciled paid grants are evaluated separately.
3. Entry retries can recover a missing mirror, including after the same email is verified on a replacement account. Existing timestamp or decision conflicts remain in review, retaining the original evidence. Only an authoritative conditional registry write may establish a new interval.
4. An active verified admin can submit a browser-protected POST to `/api/admin/trial-recheck` with a target `userId`. It only reads registry evidence and audits the outcome. The response and audit details contain no key, fingerprint, decision, or email. Review unresolved cases before reopening the restored trial population. The bulk recovery drill and release checks are tracked in Task 22b.
